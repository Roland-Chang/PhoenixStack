PhoenixStack Topology

L5 design, updated 2026-11-27. Every guest runs on pve01; each zone is a VLAN on its bridge vmbr0.

Decided in this picture

  • Three zones: DMZ (VLAN 200), Services (VLAN 100), Management (VLAN 10).
  • Cloudflare proxies the public web apps; the public Traefik has a Cloudflare Origin CA certificate, so no API token sits in the DMZ.
  • Two Traefik instances: a public one in the DMZ with only public routes, and a Services one for LAN and VPN users.
  • Names follow who reaches the app: <app>.phoenixstack.net for general users from anywhere (public Traefik; works at home too), <name>.int.phoenixstack.net for LAN and VPN only (Services Traefik). int. isn't admin-only; the UDM rules decide that.
  • Authentik lives in Services. The public Traefik asks it to log people in (forward-auth); its database never leaves Services.
  • Public apps log in with their own OIDC against Authentik (auth.phoenixstack.net). Users sign in there with their Google account (each person created by hand, no open sign-up); admins with a password and a YubiKey. Groups: Family, with Young and Porter below it.
  • One Docker host per zone, as VMs: docker01 (Services) and docker02 (DMZ), like docker-temp today.
  • Every public app runs on docker02 with its own database (no database guest in the DMZ). It reads the NAS's Media and Porter shares read-only, as its own NAS user, and writes only to shares of its own: Podcasts (Audiobookshelf) and Immich.
  • Simple native services run as containers: Pi-hole, PostgreSQL, MariaDB.
  • Testing before production: app upgrades on a staging copy (<app>-staging.int, copied data); role and host changes on throwaway test guests. Pilot: Audiobookshelf.
  • Every guest may only send from its own address (Proxmox IP filter), so the rules between guests can trust the source address.
  • Each GPU belongs to one VM and is shared by the containers inside it: P2000 for media, RTX 5060 Ti for AI.
  • Addresses: MAC 02:aa:bb:cc:XX:YY, VMID 1XXYY, last octet = code × 10 + instance (pgsql01 = 10701, .71), the same in every zone.

Still open

  • Which of docker-temp's other apps are public (to docker02) and which LAN and VPN only (to docker01)? The first list is decided.
  • An off-host Pi-hole (Porter network), so DNS survives a pve01 reboot; ad blocking comes with it.
  • Monitoring (uptime and service alerts) and central logs (SIEM): which zone and when.
  • Hardware, later: a 4th 990 Pro drive (the data pool's second mirror) and 4 more DIMMs.

Still open

  1. Outbound DNS from IOT (53, 853) to the internet: still to block. IOT gets internal names through the UDM's forward to Pi-hole (2026-11-22), so it needs no rule into Services.
  2. Teleport clients count as admins. The whole Teleport range (192.168.2.0/24) is an admin source, with all ports into Management. Fine while only admins use Teleport; before anyone else does, give admins fixed Teleport addresses and list only those.
